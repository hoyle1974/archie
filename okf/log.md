## 2026-10-03
- M5 step 4 built: "which one did you mean?" (vignette Q passes). When the item picker says the user means one item and several fit, or the understanding call can't tell which of Archie's open questions a reply answers, code asks "Which one: A or B?" and saves the options as `pending` in the conversation entry (`archie/ask/which.py`). The next message within 30 minutes answers it, matched by code first (a number, "the first one", or a word only one option has), otherwise as an `answer` part from the understanding call, which is shown the question; the original request then runs on the chosen item. Any other message, or 30 quiet minutes, drops it.
- M5 step 3 built: instructions (vignette P passes). Every instruction now runs through one action list (`archie/ask/actions.py`) whose replies say what the code did. The understanding call picks the action; for open items the fast model only picks which ones, and code writes "Snoozed until Monday: HeadphonesRUs, earbud pairing." Sending gets "I can't send anything; I only read."; anything else Archie can't do gets "I can't filter Today by day yet. I've saved that you want it.", is saved in `journal/told.md` and logged as a gap, and anything told in the same message is saved and said first. `remember`, `correct` and `clarify` are no longer intents (`archie/ask/remember.py`, `correct.py`, `clarify.py`); the `loop_update` intent is gone.
- Branch review fixes for step 3: words code puts mid-sentence keep the capitals of "I", acronyms and names Archie knows; snoozed items can be marked done, dismissed or re-snoozed; an action the model invents parses as none (a lenient `choice` field) instead of failing; a snooze date must be in the future; the item picker also sees the understanding call's `target`.
- Live check of step 3 (4 messages, under 1¢; 2–3 s each). "only show work stuff on weekdays" got "I can't only show work stuff on weekdays yet. I've saved that you want it." (the model's `wanted` repeated the words), saved in `journal/told.md` and logged as a gap. "email Workpersonthree that the pizza's picked up" at first came back as one send part, so the news wasn't saved; the understanding prompt now says news to send is also a telling, and after that it and "text Workpersonfour that the IEP form is signed" got "I saved that … I can't send anything; I only read." with the news saved.
- M5 step 2 built: telling Archie something (vignette N passes). Every telling, and every answer to one of Archie's questions, is saved word for word in `journal/told.md`, then applied by `archie/ask/tell.py`: facts about a person (the `remember` code, no longer an intent), ignoring or un-ignoring a sender, or "Saved. I don't use that for anything yet." (logged as a gap). Ignoring (`archie/derive/ignore.py`) writes a new top-level `ignore:` list in `config.yaml` (read together with `loops.mute`), flags the dossier, dismisses the sender's open items, stops questions about them, and leaves their mail out of answers unless the question names them. Email excerpts now record their sender (`sender` column, index schema 3), which also lets "the message I sent them" search the user's own mail first (`mine`). An empty answer with nothing dropped now says "none of it answers that" instead of "couldn't verify".
- Live check of step 2 (4 messages, about 3¢ in total; `archie admin reindex` took 47 s for 1,351 files). "ftbrmktf@sxziiqsov.us is spam, ignore it" was understood as an answer to the open "Who is …?" question with `fact: ignore`. Code replied "I'll ignore Goodcompany (ftbrmktf@sxziiqsov.us)… Say "stop ignoring Goodcompany" to undo.", the question resolved, the address is in `config.yaml`'s `ignore:` list, and `journal/told.md` has the line. "do you see the message I sent them?" after "did Status reply about my earbud?" now cites the user's own sent messages to HeadphonesRUs (step 1 found none). "I prefer short answers" got "Saved. I don't use that for anything yet." and was logged as a gap. The two search answers took about 15 s each.
- M5 step 1 built: `ask` now understands each message into parts with the recent conversation (`state/conversation.jsonl`) and open questions in view, replacing the menu router (`archie/ask/understand.py`, `dispatch.py`, `conversation.py`, `followup.py`). "show N" and "really?" work without a model call. Vignette O passes. Tests now hand the fake model the new `PART` format directly.
- Live check of step 1 (5 messages, about 4¢ in total; the understanding call is 0.13–0.32¢). "them" was filled in correctly ("…the message I sent HeadphonesRUs about the earbud replacement?"), "show N" answered in 8 ms with no model call, and "really?" re-asked the rewritten question. Found: (1) search returned only HeadphonesRUs's emails, none of the user's own sent replies, so the follow-up answer was empty. Retrieval needs to know who sent a chunk (step 2). (2) "<address> is spam" was understood as an answer to the open "Who is …?" question and reached `remember`, which replied "I didn't catch who that was about" (step 2's told record and ignore list fix this). (3) An empty answer from the model is shown as "couldn't verify" even when no claim was dropped.
- Branch review fixes for step 1: a mixed message's cited replies now share one citation numbering; "really?" never redoes a telling, notes or an answer; names in rewrites and ask-backs must be whole words someone said, and unheard `people` are dropped; pasted lines can't open a record or change a part's kind (record keywords match in any case only when followed by a single word); a "show" with no clear number asks which; a failed conversation write no longer loses the answer. Not fixed yet: an answer to one of several yes/no questions reaches `clarify` without its question number, so `clarify` maps it again.
- Design for M5 "Understand first" (spec: `docs/superpowers/specs/2026-10-03-understand-first-design.md`, not built yet). `ask` will first split each message into parts (question, telling, instruction, answer to an open question, unclear) with the recent conversation in view, then send each part where it belongs. New vignettes N–R in `docs/VIGNETTES.md`: telling Archie something, follow-ups, "I can't do that yet", "which one did you mean?", and nudges.
- The model backend is now Gemini (`google-genai`), and replies use a plain line format instead of JSON schemas (`archie/llm/shape.py`). Each call declares a `Shape`; code writes the format instructions, parses and checks the reply, and retries once. Schema-forced JSON cost tokens and was less reliable. The Claude backend is removed (it's in git history). Spec: `docs/superpowers/specs/2026-10-03-gemini-line-format-design.md`.
- Gemini live check: `gemini-3.7-flash` (fast) and `gemini-3.1-pro-preview` (strong) both answered. A cited search answer kept 4 claims and dropped 2 whose quotes were real but credited to the wrong source; a who answer dropped none; `remember` saved Sam. Measured cost: about 3–4¢ per strong-tier answer (mostly Pro thinking tokens), about 0.2¢ per fast call. Found and fixed: used-up prepaid credits (HTTP 402) were reported as a rate limit, and the SDK printed an automatic-function-calling warning.
- Written answers (the `strong` tier) now use `gemini-3.7-flash` instead of `gemini-3.1-pro-preview`. On the same two questions Flash dropped no claims (Pro dropped 2 on one), answered in about 10 seconds instead of 20, and cost about 1.3¢ instead of 3–4¢.
- Derivers stop retrying an item after 3 failures caused by the item itself (`archie/derive/failures.py`, `state/llm_failures.yaml`). Before, a thread whose reply could never be read cost a model call every 15-minute sync. Outages and quota errors don't count, so they can't make Archie give up on mail. Doctor lists skipped items.
- Branch review fixes for the line format. Multi-line pasted notes are now saved whole, from the user's own text, and lines like `Topic:` inside them can't change where the notes are filed. Quotes the model wraps in quote marks still verify. A reply cut off at the output limit, or a records-only reply with no blocks and no `NONE`, is now treated as unreadable instead of "nothing found", so the thread is retried rather than marked done.
- Archie now has its own monthly model budget (`llm.monthly_budget_usd`, default $15; `archie/llm/budget.py`). Every Gemini call's token counts and cost are logged to `logs/llm_usage.jsonl`, and once the month's total reaches the limit Archie stops calling the model until the 1st. Asks then say so plainly (CLI and TUI), and background work waits. Doctor shows the month's spend. This sits under Google's own billing caps, which are set per billing account and far higher.
- The TUI shows Gemini spend this month in the Ask pane's border, refreshed every 3 seconds from `logs/llm_usage.jsonl`. Google has no API for the prepaid balance, and billed cost is only readable through a BigQuery billing export that lags up to a day, so the figure is computed from the token counts Gemini returns with each reply.
- Sync reports what it's waiting on (`on_progress`): the sources still running, then the deriver, index or final-check step. Derivers now run in a worker thread so the TUI keeps redrawing while they call the model.
- People with the same full name are no longer merged on the name alone. A merge now also needs the same email username, and otherwise Archie asks. Two different people with one name would have been folded together, with no way to undo it.
- Sync orders connectors with `graphlib.TopologicalSorter` instead of a fixed two-wave split, so `after` chains of any depth work.
- Due dates are parsed by code from the verified quote (`archie/derive/dates.py`) for email, Jira and meeting-note loops. Before this, the model's date was used, which broke DESIGN §2.5. The model's schema no longer has `due`.
- Vignette tests now check what the user sees: rebuilding once after an edit (A), names and emails resolving to one person and ambiguous names (B), the same ask in email and Jira (C), "next Wed" in notes (H), and open items with the person (J). Parts that aren't built yet are strict `xfail` tests, and A, B, C and J are back to 🟨.
- DESIGN: the intent table lists `remember` and `clarify`. The example dossier no longer stores recent interactions, matching §5.2.

## 2026-10-02
- Drafted the design for `now` as a source (`docs/superpowers/specs/2026-10-02-now-source-design.md`). Waiting on the auth choice; no code yet.
- Fixes from the first real use of the TUI:
  - Sync failed with "bad value(s) in fds_to_keep" because tqdm's multiprocessing lock can't spawn under Textual. tqdm now gets a thread lock.
  - Copying didn't work because macOS Terminal ignores OSC 52. Copying now also uses `pbcopy`, and Ctrl+Y copies the answer.
  - Added the single-writer lock that DESIGN §3.1 called for.
- M4 is done: all 13 vignettes have passing end-to-end tests (`tests/vignettes/`). Added the catchup and handover intents. All-hands briefings were already handled by the meeting-type template.
- M3 is done. Vignettes C, D, E, F and M pass, and A passes for standard meetings, 1:1s and standups. Added GitHub (live through `gh`) and Jira (fakes only), GitHub review-request loops, cross-channel closure, the activity module, the ledger, the weekly journal and code-computed standup sections.
- Classifier change: an explicit title keyword (standup, all-hands) now wins over structure, so a 2-person "Daily Standup" stays a standup.
- A loop more than 7 days past due is marked "still needed?". The live archive showed a long-overdue item ranking as most urgent.
- GitHub logins join a dossier automatically when the public profile name matches exactly one person.
- M1 and M2 are done. Vignettes B, H, J and L pass. A passes for standard meetings and 1:1s, and C passes for email.
- People: inbound mail counts toward a dossier only if Gmail filed it as Personal (or the account has no categories), and never from a role address. Real data had shown 48 "people", mostly businesses, which these rules cut to 16.
- An invite to a future meeting introduces a person but is not an interaction. "Last talked" and history only count things that have already happened.
- Connectors can declare `after = (...)`. Drive runs after Calendar because it reads calendar attachments.
- Vignette tests use `tests/vignettes/week.py`, a synthetic week synced through the real connectors (backed by fake Google services) and the real derivers, together with a deterministic `HeuristicLLM`. Tests check code-computed output, plus what the model was shown (`llm.saw(...)`) for LLM-written facts.
