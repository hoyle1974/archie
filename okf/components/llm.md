- `backend.py`:
  - `GeminiBackend` calls the Gemini API through `google-genai` with plain text in and out (no tools). It reads the key from the Keychain item `gemini-api-key` once per process, caps output tokens per tier (`llm.max_output_tokens`), sets a thinking level per tier (`llm.thinking`, `off` to omit), switches off the SDK's automatic function calling, and turns prepaid-credit, quota, key, model, server, network, timeout, safety and empty-reply failures into one-sentence `LLMError`s.
  - `GemmaBackend` calls a local Gemma model (`llm.gemma_model`, default `gemma4`) through Ollama's `/api/chat` (`llm.gemma_host`, default `http://localhost:11434`), plain text in and out, no tools, no cost. Both tiers use the same model. Calls serialize on one `threading.Lock` (the request is wrapped in `with self._lock:`) since every caller — dig rounds, concurrent asks, the derivers' `ThreadPoolExecutor` pools — shares the same local hardware, and running two at once would only slow both down. No per-call timeout either (`timeout=None`): a local generation that's merely slow shouldn't be killed, unlike a stuck network call to a remote API. Connection and "model not pulled" failures still become one-sentence `LLMError`s.
  - `backend_label(backend)` names the active backend ("Gemini"/"Gemma") for the TUI's Ask pane border and the `archie ask` CLI output.
  - Every `generate()` call on either backend appends `{ts, backend, model, tier, call}` to `logs/llm_calls.jsonl`, regardless of `llm.log_prompts`, so which model answered is always on record.
  - `FakeBackend` replays canned replies for tests.
  - `make_backend(config, home, backend=None)` picks Gemini or Gemma; the `backend` argument (set from the CLI's `--gemma`/`--gemini`, default `gemma`) overrides `llm.backend` from config.yaml. Only Gemini gets the monthly budget.
- `budget.py`: Archie's own monthly spending limit (`llm.monthly_budget_usd`, default $15). Each Gemini call's reported token counts and cost go to `logs/llm_usage.jsonl`, with `call` (the shape name, from the `CALL` context variable `complete` sets) and `cached` (input tokens Google served from its cache; `gemini-3.7-flash` reported none in a probe, and they're billed at full price here so the budget never undercounts). With `llm.log_prompts: true`, `GeminiBackend` also writes each call's exact system prompt, user message and reply to `logs/prompts/<time>-<call>.md` for prompt review. Before each call the UTC calendar month's total is added up, and at the limit the call is refused with an `LLMError` that says when it resets. That error isn't caused by the item, so the derivers' retry cap doesn't count it. Prices per model are in the code with the date each applies from (Flash doubles on 2027-01-01); an unknown model is counted at the highest listed rate. A call already in flight can overshoot by that one call. `session_usd` adds up the calls this process made (a TUI session or one command); `archie admin sync` ends with "Gemini: $0.03 this session".
- `google_usage.py`: Google's own count of this month's Gemini tokens, checked against Archie's log at the end of every [sync](sync.md) when `llm.google_project` is set (e.g. `archie-email`). It reads Cloud Monitoring on that project with Archie's Google sign-in (`monitoring.read`, read-only; the project is the quota project): output tokens (thinking included) per model from `generate_content_usage_output_token_count`, and input tokens per model from every paid tier's `quota/generate_content_paid_tier[_N]_input_token_count/usage` metric, since the metric name follows the account's usage tier. Both sides are priced with `budget.py`'s table (Google's `gemini-3.1-pro` is priced as `gemini-3.1-pro-preview`) for the UTC month up to 5 minutes ago, because Google's figures arrive about 2½ minutes late. The result, or the reason the check failed, goes to `state/google_usage.yaml`. More than $1 apart is a warning in the TUI, `archie admin sync` and the [doctor](doctor.md). Usage from scratch Archie homes (live checks) counts on Google's side only.
  - Tiers: both `fast` and `strong` map to `gemini-3.7-flash` by default (`llm.models`); `strong` gets a larger output cap and medium thinking.
- `shape.py`: each model call declares a `Shape` (fields, records, or cited claims). It writes the format instructions appended to the system prompt, parses the plain-text reply into the dict the caller uses, and reports problems; `TextBackend.complete` retries once on a problem. No JSON or schema is sent. Reading rules that guard against silent loss: a records-only reply with no record and no `NONE` is a problem, the first value of a top-level key wins (so lines inside pasted text can't override it), `quote` fields drop wrapping quote marks before the exact-match check, and a Gemini reply cut off at the output limit is an error even when it has text. A claim line whose last citation opens a double quote that never closes is joined to the next line (`_joined`): the model had copied a line break from plain-text mail into a quote, and the tail (`start."`) showed as its own claim (review 2026-10-04 evening). `_reorder_trailing_cite` rewrites a `"quote" [n]` line (the citation after its quote) to the requested `[n] "quote"` before the normal citation scan runs, skipping a bracket that's already immediately followed by another quote (an existing multi-citation line) so it's never merged into one. Without it, the bracket read as a bare, quote-less marker — always a verifier drop regardless of backend, but Gemma writes this order far more often than Gemini (2026-10-11 review: 12 of 13 citations dropped in one live answer, all this pattern). The actual verbatim-match check in `verify.py` (below) is unchanged; this only fixes which text a citation's quote is read from.
- `verify.py`:
  - A `Packet` holds numbered excerpts, and the model cites `{ref, quote}`. `render` wraps each in `<source n=…>` with `[n] label` first (emails contain brackets, so bare `[n]` lines were ambiguous) and shows `tidy(text)`: without YAML frontmatter, HTML comments (fences, hidden citation blocks), long tracking links, images, unsubscribe footers, and with email header times in local time. Quotes are still checked against the original text. An excerpt that tidies to nothing (a notes file holding only data) isn't shown. `note` carries code-computed context shown after an excerpt (a repeating event's other dates). `check_quote` also rejects hollow quotes that are verbatim but show nothing: names and addresses only, a greeting line, a subject line. Search results carry a `match` score (0–1, relative to the best source) shown as `· match 0.82`; the answer prompt says sources come best first and that the score is a hint, not proof.
  - `verify_claims` keeps a claim only if at least one quote appears verbatim in the excerpt its ref points to. Whitespace, case and curly quotes are normalized, and quotes must be at least 8 characters.
  - Everything else becomes an `Unverified(text, near)` in `dropped`: `near` names the label of any cited ref that resolved to a real packet item even though its quote failed (deduplicated; empty when the claim had no usable citation at all, or none of its refs resolved). Never shown as fact (2026-10-11 review) — [ask](ask.md)'s `Answer.unverified` carries it through so it can still be shown, labeled.

Enforces [cited LLM output](../principles/cited-llm-output.md). Design: [DESIGN §9](../../docs/DESIGN.md#9-llm-interface).
